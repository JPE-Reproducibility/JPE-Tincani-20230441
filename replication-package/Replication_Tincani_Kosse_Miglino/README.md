# 1. Overview

This replication package reproduces all tables, figures, and in-text numerical results reported in:

> Tincani, Michela M., Fabian Kosse, and Enrico Miglino.  
> Beliefs and the Incentive Effects of Preferential College Admissions: Evidence from an Experiment and a Structural Model.

The package contains:

- All code necessary to reproduce the empirical and structural results.
- All raw datasets that the authors are permitted to redistribute.
- Instructions to regenerate all tables, figures, and in-text numbers.

The folder `output/` should be empty when received by replicators.  
All results are generated by running the code as described below.

### Notes

- All files inside `output/`, `data/processed/`, and `confidential-data-not-for-publication/processed` are generated by the replication scripts.
- The folder `data/raw` contains all data inputs that the authors are permitted to redistribute publicly.
- The folder `confidential-data-not-for-publication/raw` is intended to store restricted administrative datasets that cannot be publicly redistributed. In the publicly deposited replication package, this folder will be empty.
- Researchers seeking to fully replicate the results must independently obtain the restricted datasets and place them in this folder.
- The folder `code/stata` contains all Stata do-files used in the analysis,  and the subfolder `ado_frozen/` contains the frozen user-written Stata ado dependencies used by the scripts. The folder `HPC_scripts_logs` contains the submissions scripts used on the UCL'Myriad HPC as well as the logs from the runs on the HPC.
- The folder `code/julia` contains all Julia scripts used for the structural model estimation, simulations, and bootstrap standard errors. The files `Project.toml` and `Manifest.toml`, including the corresponding files in `bootstrap/`, record the Julia package environments used by these scripts, with `Manifest.toml` locking the exact package versions needed to reproduce the computations.






# 3. Data Availability and Provenance Statement (DAS)

## 3.1 Statement About Rights

The authors have legitimate access to and permission to use all data employed in this manuscript.

Some datasets originate from Chilean public institutions:
- Ministerio de Educación, Chile  
- Agencia de Calidad de la Educación, Chile 
- Departamento de Evaluación, Medición y Registro Educacional (DEMRE), Chile

The authors do not hold redistribution rights for certain administrative datasets beyond the permissions granted by the respective institutions. Full replication may therefore require independently obtaining restricted datasets from the originating institutions.

## 3.1.1 Data Preservation and Replication Support Commitment

In accordance with the Journal of Political Economy data and code policy, the authors commit to preserving all restricted-access datasets used in this study for a period of no less than five years following publication of the paper.

The authors further affirm support for replication efforts. In particular, the authors will provide reasonable assistance to requests for clarification and replication by researchers who independently obtain access to the data.

## Step 3: Julia Bootstrap Standard Errors

Bootstrap standard errors for the structural model are computed separately from the main pipeline. Before running any bootstrap Julia file, activate and instantiate the bootstrap environment as described in Section 4.2. This setup must be performed using Julia 1.11.1.

The Stata pipeline creates 53 block-bootstrap samples in Step 1, through `13.Create_bootstrap.do`.

The final bootstrap standard errors are based on 50 bootstrap estimates, labelled 1 through 50. For most bootstrap labels `x`, replicators should run:

`Estimation_s_bootstrapx.jl`

Each such Julia file reads the corresponding bootstrap inputs:

- `initial_conditions_TC_bootstrapx.dta`
- `empirical_coefficients_rescale_bootstrapx.dta`

and writes:

- `estimation_theta_s_bootstrapx.csv`
- `estimation_output_s_bootstrapx.txt`

where `x` is the bootstrap label. A common file used across all bootstrap samples is:

- `parameters_estimated_outside_rescale.dta`

Three bootstrap samples required special handling because the original samples labelled 12, 24, and 36 had convergence issues. The Stata pipeline therefore creates additional replacement bootstrap samples. Replicators should use the following mapping:

| Bootstrap label used in standard-error calculation | Julia file to run | Bootstrap input sample read by the Julia file |
|---|---|---|
| 12 | `Estimation_s_bootstrap51.jl` | 51 |
| 24 | `Estimation_s_bootstrap24.jl` | 53 |
| 36 | `Estimation_s_bootstrap52.jl` | 52 |

Thus, `Estimation_s_bootstrap12.jl` and `Estimation_s_bootstrap36.jl` are intentionally not included. The files `Estimation_s_bootstrap51.jl` and `Estimation_s_bootstrap52.jl` should be run instead; they save their outputs using labels 12 and 36, respectively. Similarly, `Estimation_s_bootstrap24.jl` reads bootstrap sample 53 but saves its outputs using label 24.

After completing the bootstrap stage, replicators should have exactly 50 parameter-vector CSV files:

`estimation_theta_s_bootstrap1.csv` through `estimation_theta_s_bootstrap50.csv`

These 50 labelled outputs are the inputs used to compute the bootstrap standard errors.




Each bootstrap estimation is independent. Replicators may therefore run bootstrap estimations in parallel, by submitting one job per bootstrap sample on their own cluster environment. 

Note to replicators:

For convenience, the replication package also provides the 50 completed bootstrap parameter-vector files, `estimation_theta_s_bootstrap1.csv` through `estimation_theta_s_bootstrap50.csv`, inside `code/julia/bootstrap`. Therefore, replicators who wish to reduce runtime may test the bootstrap procedure by rerunning only a small number of bootstrap estimation jobs, rather than all 50, and verifying outputs against the provided .csv files. If doing so, they should take care with the three special bootstrap labels described above: labels 12, 24, and 36 are produced using replacement bootstrap samples, so rerunning those labels requires using the corresponding mapped Julia files and input samples. After these checks, the replicators should copy all `estimation_theta_s_bootstrap1.csv` through `estimation_theta_s_bootstrap50.csv` files inside `confidential-data-not-for-publication/processed`, to ensure that the python helper files described below runs without errors.


The authors executed the bootstrap estimations in parallel on the UCL Myriad HPC cluster. Because cluster submission systems differ across institutions, this replication package does not impose a cluster-specific submission script on replicators. Replicators who wish to run the bootstrap stage in parallel should adapt the submission logic to their own system. The bootstrap stage is computationally demanding and is documented separately in Section 7.2.

The primary data collection was school-based survey and achievement-test fieldwork, not a laboratory experiment. The treatment studied in the paper was the national PACE policy. The school-level randomization was conducted by PNUD Chile for the Chilean government; the research team advised on the design but did not execute the randomization or administer the policy treatment.

Before the nationwide data collection, the research team designed and piloted the student, teacher, and principal surveys. The team also conducted student focus groups in collaboration with its in-country fieldwork partner, Consultoría FOCUS (`https://focus.cl/`). The FOCUS project manager was Magdalena Sánchez A. The focus groups were conducted in schools identified through FOCUS’s longstanding education-sector fieldwork network in Chile and were used to refine the survey instruments before delivery in the sampled schools.

The subject pool consisted of students in the experimental cohort attending the sampled PACE-eligible schools. The government randomly assigned 64 of 221 eligible schools to receive PACE. The research sample includes all 64 treated schools and, for budget reasons, 64 schools randomly selected from the 157 schools assigned to the control group. The Ministry of Education, through the head of the PACE programme, sent letters to school principals encouraging participation in the data collection. Generic versions of these principal letters, with identifying school/principal information removed, are included in `supporting-material/` as `carta DIRECTORES PACE.docx` and `carta DIRECTORES NO PACE.docx`. All sampled schools agreed to participate. Fieldworkers visited schools and administered the materials to students who were present. The student fieldwork covered 6,534 students.

The fieldwork took place in Chilean schools between September and November 2017, while students were in 12th grade. Data collection was conducted manually using paper questionnaires during class time; it was not online and did not use computers for administration. A typical student session lasted approximately 40-50 minutes. Students first completed a 20-minute mathematics achievement test and then proceeded to the survey questionnaire. The achievement-test questions were developed by Aptus Chile and Puntaje Nacional and were piloted extensively. To reduce cheating and fieldworker influence, the team produced six versions of the achievement test with different question orders. Questions were assigned to three difficulty categories, and the order of questions was randomized within category so that all students faced questions of increasing difficulty. Students were told that not all students had identical tests.

Instructions were printed on the first page of the student materials and read aloud by fieldworkers. The student information sheet explained that participation was voluntary, that responses would be treated confidentially, and that the study had ethics approval from the University of London Research Ethics Committee, project ID 10515/002. No separate comprehension quiz, practice trial, or matching protocol was used, because this was not a game-theory or laboratory experiment. Fieldworkers used standardized procedures, acted as invigilators during the achievement-test portion, and submitted checklists to supervisors to harmonize implementation across schools.

Students did not receive show-up fees, grades, artificial currency, or monetary payments. The only incentive was a lottery for an iPad: each correct answer on the achievement test increased the number of tickets a student received for the final lottery, which was announced in the student information sheet. There was no exchange rate, average experimental earning, or performance payment other than this lottery mechanism.

There was no matching of subjects and no use of deception. The questionnaires did not display logos of the Ministry of Education or any public agency. No instructional inaccuracies were intentionally introduced.

 The pre-analysis plan is in the AEA RCT Registry (AEARCTR-0002288). The research received ethics and data protection approval at UCL (10515/002 and Z6364106/2017/06/101), with relevant documentation reported in this package's supporting material folder.
